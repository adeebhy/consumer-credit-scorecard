# End-to-End Consumer Credit Risk & Scorecard Modeling Framework

Roll-rate analysis, monotonic WoE binning, a points-based scorecard (600 @ 50:1, PDO 20), EAD/LGD/EL estimation,
validation with PSI/CSI monitoring, and a FastAPI scoring service. Built on the real **UCI Default of Credit Card Clients**
dataset (30,000 accounts). All notebooks are executed, so the numbers below are real outputs.

```
Expected Loss (EL) = PD x LGD x EAD          Score = Offset + Factor x ln(odds_good)   (Factor = PDO/ln2 = 28.85, Offset = 487.12)
```

## Results (test sample, 9,000 accounts, bad rate 22.1%)
| Metric | Threshold | Train | Test | Status |
|---|---|---|---|---|
| Gini | >= 0.50 | 0.549 | 0.523 | Pass (bootstrap 95% CI [0.494, 0.546] - the lower end is below 0.50) |
| AUC | >= 0.75 | 0.775 | 0.762 | Pass |
| KS | >= 40% | 41.5% | **39.6%** | **Fail, narrowly** |

- **Scorecard:** 13 variables, all WoE profiles monotone (25/25 numeric), every coefficient negative and p < 0.05. PAY_1 (latest repayment status) carries the most weight.
- **Stability:** score PSI train->test **0.001 (stable)**.
- **Drift simulation (synthetic shift):** oversampling delinquent customers 3x gives PSI **0.207 (moderate - review)**. Predicted PD 31.4% vs observed 30.8%, so calibration still held: a pure covariate shift needs a review, not a recalibration.
- **EAD/EL:** mean CCF proxy 0.178 (median ~0). Test-portfolio EL is 14.3% of EAD. This is on the dataset's 1-month default horizon, not annualised.
- **API:** `/score` returns score, PD, risk band and 3 reason codes. A test confirms API score == batch score.

## What differs from the original README (stated plainly)
1. **No origination-cohort vintage analysis and no out-of-time holdout.** The data is one 6-month snapshot with no origination dates. A stratified 70/30 split is used instead, plus a roll-rate analysis (real).
2. **Roll-rate results:** the 90+ DPD cure rate is **10.7%, not < 10%**, so the "point of no return" threshold is narrowly *not* met. The 30 DPD row (0.0% cure) rests on **only 34 observations**, because status "1" almost never appears before September in this dataset (a recording quirk), so ignore that row.
3. **LGD uses synthetic recoveries.** The dataset has no recovery data. The two-stage LGD model (logistic + fractional logit as beta-regression equivalent) is validated on a known synthetic process: it recovers the true LGD (corr 0.999). **The LGD values are illustrative, not estimates for this portfolio.** The EL "predicted / realised = 0.93" check is therefore partly circular.
4. **EAD/CCF is a proxy** from real data: share of undrawn headroom (vs the June balance) drawn by September among defaulters; fit R-squared is low (0.06).
5. **IV > 0.5 handling:** PAY_1 (IV 0.86) trips the leakage screen. It is the latest delinquency status *before* the outcome month, not derived from the target, so it is kept after review. Strictly dropping it cuts test Gini from 0.523 to 0.454.
6. **SEX and MARRIAGE are excluded from the scorecard** (ECOA-protected); their IV is still reported. AGE is retained.
7. **OptBinning not used:** binning is a custom implementation (monotone merging), per the original repo layout. Not benchmarked against OptBinning.
8. Not a validated production model: no macro/through-the-cycle calibration, no challenger model, no regulatory sign-off.
